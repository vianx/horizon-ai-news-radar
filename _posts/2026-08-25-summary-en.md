## [FDA Approves First Wearable for Continuous Ketone and Glucose Monitoring](https://www.fda.gov/news-events/press-announcements/fda-authorizes-first-wearable-device-continuously-monitors-both-ketone-levels-and-blood-sugar) ⭐️ 8.0/10

The FDA has authorized the first wearable device that continuously monitors both ketone levels and blood sugar, marking a significant regulatory milestone in diabetes technology. This clearance paves the way for more integrated metabolic monitoring in daily life. This device could greatly improve diabetes management by providing real-time data on both glucose and ketones, helping to prevent dangerous conditions like diabetic ketoacidosis. It may also benefit people on ketogenic diets or those with metabolic disorders, and could drive further innovation in non-invasive or minimally invasive wearable sensors. The device uses a wearable sensor to continuously measure both biomarkers, likely via interstitial fluid, and transmits data to a companion app. While the FDA clearance is a first, the device may still require fingerstick calibration for accuracy, and its availability and reimbursement status are not yet clear.

hackernews · sunnynagra · Aug 25, 19:07 · [Discussion](https://news.ycombinator.com/item?id=49439017)

**Background**: Continuous glucose monitors (CGMs) have been widely used by people with diabetes to track blood sugar levels in real time, but ketone monitoring has traditionally required blood or urine tests. Ketones are produced when the body breaks down fat for energy, and elevated levels can indicate diabetic ketoacidosis, a serious complication. The FDA's 510(k) clearance process requires devices to demonstrate safety and effectiveness, and this new device combines two important metabolic metrics into one wearable.

## [EVE Online Begins Massive Python 3 Migration](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/) ⭐️ 8.0/10

EVE Online announced the start of its migration from Stackless Python 2.7 to Python 3, using the futurize script on 2.4 million lines of code and manual review of ~20,000 behavioral differences. This migration is significant as it demonstrates a strategy for upgrading a massive, long-running Python codebase, providing insights for other large-scale projects facing similar challenges. It also highlights the ongoing need to move away from deprecated Python 2.7 and Stackless Python. The migration will use the futurize script to automate conversion, followed by manual review of approximately 20,000 places where Python 2 and 3 behavior differ, such as integer division. The announcement does not specify how they will replace Stackless, but a previous presentation described using the carbonengine/scheduler library for EVE Frontier.

rss · Simon Willison · Aug 25, 22:59

**Background**: EVE Online has run on Stackless Python since 2003, with its last major upgrade to Stackless Python 2.7 in 2010. Stackless Python is a variant of CPython that provides microthreads (tasklets) for lightweight concurrency, but the project has been discontinued and its GitHub repository archived. The migration to Python 3 is a major undertaking due to the scale of the codebase and the behavioral differences between Python 2 and 3.

The report introduces Thomson, a new general-purpose frontier model trained via continual learning on open-weight models, demonstrating that frontier performance is achievable with substantially lower compute and personnel budgets. It proposes a concrete approach for SovereignAI, enabling a wider range of institutions to build and govern their own AI systems. This challenges the assumption that frontier AI development is exclusive to a few heavily funded players, potentially democratizing AI capabilities and reducing information, economic, and power asymmetries. SovereignAI refers to an organization's capability to independently build, deploy, and govern AI use, reducing dependence on foreign providers.
