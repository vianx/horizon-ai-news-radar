## [研究人员意外劫持废弃 ENUM 区域，记录军方通话](https://lina.sh/blog/hijacking-e164-arpa) ⭐️ 8.0/10

一名安全研究人员意外控制了已废弃的 e164.arpa DNS 区域（用于 ENUM 电话号码映射），并记录了数十万条电话路由查询，其中包括发往军事基地的查询。这一事件凸显了传统协议管理中的重大疏忽。 这一发现揭示了全球电话基础设施中的一个重大漏洞，由于涉及军事相关查询的暴露，可能对国家安全产生影响。它强调了对传统协议进行更好监管的必要性，并引发了关于负责任披露以及 ENUM 在现代通信中相关性的讨论。 社区评论指出，研究人员没有设置 SIP 服务器来测试查询是否导致实际呼叫终止。据评论者称，e164.arpa 区域并非完全废弃，它被私下用于通过 VPN 进行号码携带服务。

hackernews · gavide · 8月21日 13:11 · [社区讨论](https://news.ycombinator.com/item?id=49387570)

**背景**: ENUM（电话号码映射）是一种使用 DNS 将电话号码映射到互联网地址的系统，其中 e164.arpa 域被保留用于此目的。它旨在统一 PSTN 与互联网，但从未获得广泛的公众采用，并已基本废弃。e164.arpa 区域由 IETF 管理，旨在由国家当局维护，但监管上的疏忽可能导致此类漏洞。

## [让 LLM“简洁”可省钱，压缩输入则不然](https://www.reddit.com/r/MachineLearning/comments/1vulfei/does_telling_an_llm_to_be_concise_actually_save/) ⭐️ 8.0/10

一项对 9 个 LLM 的实证研究发现，指示模型简洁输出平均可节省约 1.5 倍成本（最高 3 倍），且准确率无明显下降；而压缩输入提示词则会使成本增加高达 96%，并降低准确率。 这为开发者和企业优化 LLM API 成本提供了可操作、数据驱动的指导，表明输出端压缩有效而输入端压缩可能适得其反。同时验证了 Claude Code 等提供商近期推出简洁输出风格的趋势。 该研究在九个模型（包括 GPT-4o、Claude Haiku 4.5、Qwen2.5-VL-7B、DeepSeek-R1-Distill 等）上测试了五个缩减级别，使用了五个短答案数据集、一个十一语言输出测试和一个较长摘要测试。值得注意的是，当缩短输出正确时，约有一半情况下文本不再匹配模型无约束时的推理，如果只关心最终答案，这可能可以接受。

reddit · r/MachineLearning · /u/ibubbles34 · 8月21日 16:38

**背景**: LLM API 成本主要基于 token 计费，通常输出 token 单价高于输入 token。提示词压缩是一种常见的成本节约技术，但本研究表明它可能适得其反，因为模型可能生成更长的输出来补偿缺失的上下文。输出风格（如 Claude Code 的“简洁”模式）正成为一种用户友好的控制冗长程度的方式。
